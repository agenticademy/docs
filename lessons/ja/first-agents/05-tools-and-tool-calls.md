# ツールとツール呼び出し

はじめてのエージェントを作る · 第5章（全8章） · 20分

zodでツールを定義し、モデルにバインドし、モデルが行うツール呼び出しを処理します。

## 目標

- ツールのスキーマに説明付きのフィールドを追加し、JSON Schemaが変わる様子を見ます。
- 無効な引数を送り、検証で拒否されるのを確認します。
- 確認問題に合格します。

## 本文

### ツールはスキーマ付きの関数

@langchain/core/toolsのtool(fn, { name, description, schema })は、非同期関数をツールに変えます。スキーマはzodのオブジェクトです：z.object({ order\_id: z.string().describe("The order number") })。ツールがどの引数を受け取るか、その型、どれが省略可能かを表します。

スキーマは2回役に立ちます。LangChainはそれをJSON Schemaに変換し、モデルはそれを読みます。そしてあなたのコードはそれを使い、関数が動く前にモデルが送った引数をチェックします。

### モデルに見えるもの

model.bindTools(tools)は、呼び出しのたびに各ツールの名前、説明、JSON Schemaを送るモデルを返します。関数そのものはあなたのコードの外に出ません。モデルが知っているのはこの3つが伝えることだけなので、説明はプロンプトです。モデルに向けて書き、各フィールドを.describe()で説明してください。

### ツール呼び出しとその答え

モデルがツールを使いたいとき、その応答はtool\_callsを持つAIMessageです。各呼び出しにはname、args、idがあります。あなたのコードはツールを実行し、同じtool\_call\_idを持つToolMessageで答えます。モデルは一度に複数の呼び出しを求めることがあるので、各結果をその呼び出しと組にするのがidです。

ツール呼び出し全体をtool.invoke()に渡します。ツールはargsをスキーマで検証し、関数を実行し、ToolMessageを返してくれます。argsが合わなければToolInputParsingExceptionを投げ、関数は実行されません。エージェントのループはこのエラーを捕まえ、status "error"のToolMessageとして返すので、モデルは呼び出しを直せます。第6章では、ToolNodeがこれをやってくれます。

## 確認問題

### 質問1/3

バインドされたツールについて、モデルは何を受け取りますか？

- ツールのソースコード。
- **✓** 名前、説明、JSON Schema。
- 名前だけ。

**理由:** bindToolsは各ツールをプロバイダーの形式に変換します：名前、説明、入力スキーマです。関数そのものはあなたのコードの外に出ません。

### 質問2/3

ToolMessageを、それが答える呼び出しと結びつけるものは何ですか？

- ツールの名前。
- **✓** AIMessageにある呼び出しのidと等しいtool\_call\_id。
- リストの中の位置。

**理由:** モデルは一度に複数の呼び出しを求めることがあり、同じツールを何度も呼ぶこともあります。idが各結果をその呼び出しと組にします。

### 質問3/3

モデルがorder\_idを数値で送りましたが、スキーマはz.string()です。どうなりますか？

- ツールが実行され、値を変換する。
- **✓** 関数が動く前に検証が失敗し、そのエラーをモデルに返せる。
- モデルが再学習される。

**理由:** スキーマはあなたのコードの中で強制されます。ループはエラーをToolMessageとして返せるので、モデルはもう一度試せます。

## これでできること

- tool()とzodスキーマで、役に立つ説明付きのツールを定義する。
- ツールをモデルにバインドし、そのtool\_callsを読む。
- ツール呼び出しにToolMessageで答え、無効な引数を処理する。
