# ガードレール

はじめてのエージェントを作る · 第8章（全8章） · 22分

モデルの周りに置くコードのチェック：入力と出力のチェック、ツールの許可リスト、ステップ上限を、層にして重ねます。

## 目標

- ガードを1つずつオンにして、それが何を止めるかを見ます。
- 1回の再生で4つの攻撃をすべて止めます。
- ステップ上限が何をするかを予想します。

## 本文

### モデルが言いくるめられないルール

ガードレールとは、モデルの外、あなたのコードの中にあるチェックです。プロンプトでモデルにルールを守るよう頼むことはできますが、巧妙なメッセージはモデルを言いくるめてそのルールを破らせることがあります。呼び出しを拒否するコードは、何を言われても言いくるめられません。

### 4種類のチェック

入力チェックは、モデルが読む前にユーザーのメッセージを調べ、拒否するか目印を付けます。出力チェックは、誰かが見る前に答えを調べます。たとえば、答えに書かれた金額はすべてツールの結果に出てくるものでなければならない、とすれば、モデルは金額をでっち上げられません。

許可リストは、起きてよいことを制限します。どのツールを実行してよいか、どのホストに接続してよいか、どの金額を動かしてよいか、です。既定で拒否するので、誰も載せていないツールや引数は、チケットに隠された指示が求めても拒否されます。許可リストはtoolsノードの周りに置き、ツールが動く前に拒否するようにします。

ステップ上限は暴走するループを止めます。実行のconfigにあるrecursionLimitがスーパーステップの数に上限を設け、上限に達するとLangGraphはGraphRecursionErrorを投げます。err.nameで捕まえて、わかりやすい停止に変えてください。トークンやモデル呼び出しの予算も同じように働きます。

### 層にして重ねる

1つのチェックですべてを捕まえることはできません。入力チェックは、ツールの結果として届くテキストを見ません。許可リストは答えを読みません。だから重ねて使い、1つの層が見逃しても、次の層が攻撃を止められるようにします。

専用の安全モデルも層の1つです。NVIDIAのNemotronのコンテンツ安全モデルやLlama Nemotronのsafety guardのような分類器は、メッセージを読んで安全か危険かのラベルを付けます。パターンが見逃すものを捕まえますが、これもモデルなので、コードのチェックも残しておいてください。

## 確認問題

台本モデルは常に次のツール呼び出しを求めます。何が起きますか？

コード:

```
await agent.invoke(
  { messages: [new HumanMessage("Check ticket T-48213")] },
  { recursionLimit: 6 },
);
```

- 永遠に実行される。
- **✓** 6ステップ後にGraphRecursionErrorを投げる。
- 6ステップ後に、エラーなしで最後のメッセージを返す。
- recursionLimitはサブグラフにだけ適用される。

**理由:** recursionLimitはスーパーステップの数に上限を設けます。上限に達するとLangGraphはGraphRecursionErrorを投げ、あなたのコードがそれを捕まえて、わかりやすい停止に変えます。

## これでできること

- モデルの周りに入力と出力のチェックを書く。
- 既定で拒否する許可リストでツールのノードを包む。
- エージェントのステップに上限を設け、GraphRecursionErrorを処理する。
- ガードレールを層にして重ねる理由を説明する。
