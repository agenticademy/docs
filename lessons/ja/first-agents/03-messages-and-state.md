# メッセージと状態

はじめてのエージェントを作る · 第3章（全8章） · 18分

4種類のメッセージ、会話全体を毎回送る理由、そしてLangGraphがリデューサーで状態をマージする仕組み。

## 目標

- システムメッセージを変えて、応答を比べます。
- メッセージを1つ追加し、別の1つをidで置き換えます。
- リデューサーが何を返すかを予想します。

## 本文

### 4種類のメッセージ

会話はメッセージのリストで、各メッセージには種類があります。SystemMessageはモデルへのあなたの指示です。HumanMessageはユーザーが書いたものです。AIMessageはモデルの応答で、ツールを実行する依頼であるtool\_callsを含むことがあります。ToolMessageはツールの結果を返すもので、tool\_call\_idで依頼と結びつきます。4つともすべて@langchain/core/messagesから来ます。

### モデルは何も覚えていない

チャットモデルは呼び出しと呼び出しの間に何も記憶しません。毎回リスト全体を送り、応答はそのリストだけで決まります。会話を続けるには、応答と次の質問を追加して、すべてをもう一度送ります。入力のトークン数がやり取りのたびに増えるのもこのためです。

### 状態とリデューサー

LangGraphでは、グラフがステップからステップへ運ぶデータを状態と呼びます。ノードは状態を上書きしません。更新を返し、その更新を既存のものにどうマージするかをリデューサーが決めます。リデューサーがなければ、新しい値が古い値を置き換えます。

メッセージ用に、LangGraphはMessagesAnnotationを用意しています。messagesという1つのキーを持つ状態で、messagesStateReducerでマージされます。どのメッセージにもidがあり、なければリデューサーが割り当てます。新しいidのメッセージは末尾に追加されます。リストにすでにあるidのメッセージは、そのメッセージをその場で置き換えます。idを指定したRemoveMessageはそのメッセージを削除します。グラフはこうして、たとえば古いやり取りを削るときに、リストを作り直さずに会話を編集します。

## 試す：メッセージのスタック

モデルを呼び出し、システムメッセージを変えてもう一度呼び出してから、状態の更新を送り、リデューサーがメッセージを追加、置き換え、削除する様子を見ます。

https://agenticademy.org/ja/paths/first-agents/03-messages-and-state

## 確認問題

messagesStateReducerは何を返しますか？

コード:

```
messagesStateReducer(
  [new HumanMessage({ id: "a", content: "Hi" }), new AIMessage({ id: "b", content: "Hello" })],
  [new AIMessage({ id: "b", content: "Hello!" }), new HumanMessage({ id: "c", content: "Thanks" })],
);
```

- 4件のメッセージ：a、b、b、c。
- **✓** 3件のメッセージ：a、b（内容は"Hello!"に）、c。
- 2件のメッセージ：bとc。
- bが2回現れるので例外が発生する。

**理由:** idがbの更新は既存のbをその場で置き換え、cは新しいので追加されます。

## これでできること

- 4種類のメッセージを正しく使う。
- 呼び出しのたびに会話全体を送る理由を説明する。
- LangGraphのメッセージ用リデューサーが更新をどうマージするかを予想する。
