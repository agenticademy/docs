# MCP：サーバーが提供するツール

エージェントシステムと標準 · 第1章（全8章） · 25分

エージェントがMCPサーバーのツールを見つけて呼び出す方法と、2026-07-28プロトコルが危険な呼び出しの前に人に確認する方法。

## 目標

- 返金が実行されるまでシナリオを実行します。
- ヘルプデスクの確認に自分で答えます。
- メッセージを改ざんし、本物のSDKがそれを拒否するのを確かめます。
- 確認問題に合格します。

## 本文

### ホスト、クライアント、サーバー

Model Context Protocol（MCP）は、AIアプリケーションをツールやデータにつなぐためのオープンな標準です。ホストと呼ばれるアプリケーションは、使うサーバーごとに1つのMCPクライアントを動かします。サーバーが提供するのは、ツール（モデルが呼び出せる操作）、リソース（アプリケーションが読めるデータ）、プロンプト（人が選べるテンプレート）です。メッセージはJSON-RPC 2.0で、HTTP経由か、ローカルプロセスの標準入出力（stdio）経由で送られます。

前の学習パスのエージェントでは、ツールはコード内の関数でした。MCPでは、ツールは別の誰かが書いて動かせるサーバーにあり、どのMCPホストからも使えます。

### 2026-07-28で変わったこと

この章では、公式TypeScript SDK v2とプロトコルバージョン2026-07-28を使います。ワイヤー上で3つの変更が見えます。

検出：クライアントはserver/discoverを呼び出して、サーバーのバージョンと機能を知ります。2025年のバージョンのサーバーは代わりにinitializeに応答し、SDKはそちらに切り替えます。

すべてのリクエストにバージョン：各リクエストは\_metaにプロトコルバージョンを持つので、サーバーはセッションを保持せず、どのインスタンスでもどのリクエストにも応答できます。

入力が必要：ツールに人の答えが必要なとき、サーバーはinput\_required、質問、署名付きのrequestStateを返してリクエストを終えます。クライアントは人に尋ね、その答えと同じrequestStateを付けてツールをもう一度呼び出します。サーバーは署名を確認するので、再試行は人が見た内容と一致していなければなりません。

### ツールは契約

モデルに見えるのは、ツールの名前、説明、JSON Schemaだけです。readOnlyHintやdestructiveHintなどのアノテーションはサーバーからのヒントです。クライアントは、そのサーバーを信頼する範囲でしかそれを信頼しません。このラボの返金が安全なのは、サーバー自身が確認を求めて検証するからであり、モデルがきちんと振る舞うからではありません。

### ここですること

SDKのクライアントを持つLangChainのエージェントであるHaldenのサポートエージェントと、SDKのサーバーであるHaldenのヘルプデスクが、どちらもこのページで動きます。シナリオを実行し、返金の質問に自分で答えてください。次に「傍受」をオンにし、メッセージを保留して改ざんします。本物のSDKのコードがそれを拒否します。

## 確認問題

### 質問1/4

MCPで、クライアントを動かすのは誰ですか。

- サーバー。
- **✓** ホストアプリケーション。たとえばサポートエージェント。
- モデルのプロバイダー。

**理由:** エージェントやIDEなどのホストが、接続するサーバーごとに1つのクライアントを動かします。モデルがサーバーと直接話すことはありません。モデルがツールを求めたときに、ホストが話します。

### 質問2/4

ヘルプデスクは返金の前にサポートリーダーのOKが必要です。2026-07-28のサーバーは何を送りますか。

- 入力を求める、サーバーからクライアントへの新しいリクエスト。
- **✓** input\_required、質問、署名付きのrequestStateを含む結果。これでリクエストは終わります。
- エラー-32602。

**理由:** サーバーは開いた接続で待つのではなく、リクエストを終えます。クライアントは人に尋ね、答えと同じrequestStateで再試行するので、どのサーバーインスタンスでも作業を終えられます。

### 質問3/4

再試行で返金額を上げます。サーバーが拒否するのはなぜですか。

- モデルが変更に気づくから。
- **✓** 引数が、人が承認した内容に対して発行された署名付きのrequestStateと一致しなくなるから。
- MCPは引数に金額を入れることを許さないから。

**理由:** requestStateはサーバーが署名します（ここではHMAC）。サーバーは承認された注文と金額を読み戻し、それと異なる呼び出しを拒否します。

### 質問4/4

サーバーがツールにreadOnlyHint: trueを付けています。クライアントはどうすべきですか。

- 何も変えられないのだから、誰にも尋ねずに実行する。
- **✓** ヒントとして扱い、そのサーバーを信頼する範囲でだけ信頼する。
- 実行を拒否する。

**理由:** アノテーションはサーバーの主張を表します。悪意のあるサーバーやバグのあるサーバーはツールに誤ったラベルを付けられるので、何に承認が必要かはクライアント自身のポリシーが決めます。

## これでできること

- MCPのホスト、クライアント、サーバーと、サーバーが提供する3つのものを説明できます。
- 2026-07-28の流れ（server/discover、tools/list、tools/call、input\_required、再試行）を追えます。
- 署名付きのrequestStateが、確認を人が見た内容に結びつけておく理由を説明できます。
- ツールのアノテーションを保証ではなくヒントとして扱えます。
