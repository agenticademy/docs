# オーケストレーション：スーパーバイザー、ファンアウト、サブグラフ

エージェントシステムと標準 · 第5章（全8章） · 25分

1つのLangGraphのグラフで複数のエージェントを動かすパターン：振り分けるスーパーバイザー、並列作業のためのSend、サブグラフ、各スーパーステップが保存するチェックポイント。

## 目標

- 2つの専門エージェントが同じスーパーステップで動くのを見ます。
- 入れ子のサブグラフの実行を開きます。
- 同じジョブを、1つのエージェントとスーパーバイザーで実行します。
- ファンアウトの結果を予想します。

## 本文

### スーパーステップ

LangGraphはグラフをスーパーステップ単位で実行します。各スーパーステップでは、実行すべきすべてのノードが並列に動きます。その更新は各キーのreducerで状態にマージされ、エッジが次に動くノードを決めます。メッセージは追加するreducerを使うので、2つのノードが1つのスーパーステップで両方ともメッセージを追加できます。

### スレッドとチェックポイント

MemorySaverのようなチェックポインターを付けてグラフをコンパイルし、実行するときにthread\_idを渡します。LangGraphはそのスレッドに、状態全体のチェックポイントを、入力のときに1つ、その後は各スーパーステップの終わりに1つ保存します。getState({ configurable: { thread\_id } })は最新のものを読みます。値、ステップ番号、そしてnext（次に実行されるノード）です。同じスレッドでの次の実行は、その状態から始まります。

### スーパーバイザー、ファンアウト、サブグラフ

スーパーバイザーは、次にどの専門エージェントが作業するかを決めるエージェントです。ここでは引き継ぎはtransfer\_to\_customer\_supportのようなツール呼び出しなので、モデルはほかのツールと同じようにそれを選びます。

ファンアウトは作業を並列に実行します。条件付きエッジは、ノード名の代わりにSendオブジェクトのリストを返せます。各Sendは、それぞれの入力でノードの実行を1つ始め、すべて次のスーパーステップで動きます。返されたものはreducerがマージします。

サブグラフは、ノードの中で使うコンパイル済みのグラフです。独自の状態と独自のチェックポイント名前空間を持ち、その実行は呼び出したノードの下に入れ子になります。このラボでは、Financial Analystが自分のData Engineerサブグラフを呼び出します。Commandによる引き継ぎと、状態を共有するサブグラフは、後の「高度なエージェント」のパスで扱います。

### 1つのエージェントで足りるとき

エージェントを1つ増やすたびに、モデル呼び出し、チェックポイント、引き継ぎが増え、失敗しうる箇所も1つ増えます。部分が互いに独立しているとき、1つのコンテキストが大きくなりすぎるとき、ある部分に別のツールや指示が必要なときに、作業を分けます。それ以外は1つのエージェントから始めます。

このラボでは、HaldenのサポートチームがチケットT-48213を扱います。注文48213で二重に請求された顧客です。両方の方法で実行し、トレースが測る値を比べてください。

## 確認問題

resultsには、リストを連結するreducerがあります。グラフは何を返しますか。

コード:

```
new StateGraph(State)
  .addNode("lookup", s => ({ results: [s.id * 10] }))
  .addConditionalEdges(START, () => [new Send("lookup", { id: 1 }), new Send("lookup", { id: 2 })], ["lookup"])
  .addEdge("lookup", END)
  .compile()
  .invoke({});
```

- **✓** { results: [10, 20] }：1つのスーパーステップでlookupが2回実行される。
- { results: [20] }：2つ目のSendが1つ目を上書きする。
- { results: [10] }：1つ目のSendだけが実行される。
- 例外が投げられる：1つのノードに2回Sendすることはできない。

**理由:** 各Sendは、それぞれの入力（{ id: 1 }と{ id: 2 }）でlookupの実行を1つ始めます。両方が同じスーパーステップで動き、reducerがその更新を連結します。

## これでできること

- 引き継ぎのツール呼び出しで専門エージェントへ振り分けるスーパーバイザーを作れます。
- Sendでファンアウトし、reducerで結果をマージできます。
- コンパイル済みのグラフをサブグラフとして使い、1つのエージェントで足りるときを説明できます。
- スレッド上でグラフを実行し、その最後のチェックポイントをgetStateで読めます。
