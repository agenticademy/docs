# A2A：エージェントに任せるエージェント

エージェントシステムと標準 · 第2章（全8章） · 25分

あるエージェントがAgent Cardを通じて別のエージェントを見つけ、最後まで追えるタスクを渡す方法。

## 目標

- Payments agentのAgent Cardを読みます。
- タスクをWORKINGからINPUT\_REQUIREDを経てCOMPLETEDまで追います。
- 自分のものではないタスクidに返信し、拒否されるのを確かめます。
- やり取りを正しい順に並べます。

## 本文

### ツールではなく対等な相手

A2A（Agent2Agent、プロトコル1.0）は、別々の当事者が動かすエージェント同士をつなぎます。前の章では、サポートエージェントはMCPサーバーのツール、つまりスキーマを持ち呼ばれたとおりに動く関数を呼び出しました。A2Aでは作業を別のエージェントに渡し、そのエージェントが自分のモデル、ツール、メモリでどう進めるかを決めます。呼び出し側に見えるのは、タスクとその結果だけです。

### Agent Card

A2Aサーバーにはそれぞれ、Agent Cardがあります。公開エージェントは/.well-known/agent-card.jsonでカードを提供し、誰でも認証情報なしで読めます。カードはエージェントとそのスキルの名前を示し、インターフェース（URL、JSONRPCなどのバインディング、プロトコルバージョン）を並べ、ストリーミングできるかを示し、認証の方法を宣言します。ここでは加盟店ごとのbearerトークンです。各リクエストはA2A-Versionヘッダーを持ち、サーバーはカードにないバージョンを拒否します（エラー-32009）。

### メッセージ、タスク、アーティファクト

クライアントは、パートからなるメッセージでSendMessageを呼び出します。相手のモデル向けのテキストと、注文idや金額のように確実に扱える値のための、メディアタイプ付きのデータパートです。応答はメッセージか、時間のかかる作業ではタスクです。タスクは、id、会話をまとめるcontextId、そしてTASK\_STATE\_WORKING、INPUT\_REQUIRED、COMPLETEDのような状態を持ちます。結果はチャットとは別に、タスクのアーティファクトとして届きます。

INPUT\_REQUIREDは、クライアントが答えるまでタスクを一時停止します。答えは、同じtaskIdとcontextIdを指定した新しいメッセージです。サーバーは加盟店ごとにタスクを分けて保持します。その加盟店のものではないタスクを指定した返信には-32001（task not found）が返り、何も実行されません。

### ストリーミングかポーリングか

SendStreamingMessageでは、サーバーがserver-sent eventsをプッシュします。最初にタスク、次に状態とアーティファクトの更新を、タスクが一時停止するか終わるまで送ります。ストリーミングを使わない場合、SendMessageはタスクが一時停止するか終わったときに応答します。returnImmediatelyを付けるとすぐに応答し、クライアントはGetTaskでポーリングします。

### ここですること

HaldenのサポートエージェントとPayments agentは、どちらもこのページで公式のA2A JavaScript SDK（@a2a-js/sdk 1.3.0）を動かし、それぞれ台本どおりのLangChainモデルが操作します。カードを読み、返金タスクを状態ごとに追い、その質問に自分で答えてください。次に「傍受」をオンにし、返信を別の加盟店のタスクに向けます。任意のステップでは、Payments agentがMCPで台帳にアクセスし、MCPのinput\_requiredがA2AタスクのINPUT\_REQUIREDになる様子が見えます。

3つのステップがあり、それぞれ操作は1つで、任意のステップが2つ続きます。ステップの下の図は、参加者ごとに1列、メッセージごとに1行で、上から下へ並びます。太い破線は組織の境界です。

## 確認問題

返金のためのA2Aのやり取りを正しい順に並べてください。

1. Agent CardをGETする。
2. 返金の依頼をSendMessageで送る。
3. タスクがTASK\_STATE\_WORKINGになる。
4. タスクがTASK\_STATE\_INPUT\_REQUIREDになる。
5. 同じタスクに、答えをSendMessageで送る。
6. タスクがTASK\_STATE\_COMPLETEDになり、返金の受領書がアーティファクトとして付く。

**理由:** 最初に検出があり、次にタスクが状態を移っていきます。答えはタスクのidを指定するので、サーバーは一時停止中のタスクを見つけて再開します。別の加盟店のタスクを指定した返信は何も見つけられず、-32001が返ります。

## これでできること

- Agent Cardを読み、スキルとインターフェースを選べます。
- メッセージを送り、ストリームかポーリングで、タスクの状態をアーティファクトまで追えます。
- INPUT\_REQUIREDのタスクに、同じtaskIdとcontextIdで返信して答えられます。
- MCPではなくA2Aを使うべきときを説明できます。
