# エージェントシステムと標準

中級 · 開発者向け · 全8章 · 195分

1つのエージェントをすでに作れる開発者向けです。オープンな標準を使って、エージェントをツール、ほかのエージェント、インターフェース、決済につなぎ、1つのグラフで複数のエージェントをオーケストレーションし、各コンテキストに何を入れるかを決め、実行をトレースし、攻撃に対してテストします。プロトコルのライブラリはブラウザで本物として動きます。すべてのメッセージを保留し、破棄し、改ざんできます。

## 始める前に

学習パス「はじめてのエージェントを作る」、または同じ知識：LangChain.jsのメッセージとツール、LangGraphのグラフ、エージェントのループ。

## 修了するとできること

- 2026-07-28プロトコルでエージェントをMCPサーバーにつなぎ、人への入力の依頼も扱えます。
- A2AのタスクとAgent Cardで、ほかのエージェントに作業を任せられます。
- AG-UIでエージェントの作業をインターフェースへストリーミングし、A2UIで安全なUIを記述できます。
- UCPとAP2が、エージェントの購入を人の署名付きの同意にどう結びつけるかを説明できます。
- スーパーバイザー、Sendによるファンアウト、サブグラフでエージェントをオーケストレーションできます。
- 検索、追い出し、サブエージェントでコンテキストを設計し、LangSmithの形式で実行をトレースできます。
- OWASPのエージェント型リスクを地図として、プロンプトインジェクションと改ざんに対してエージェントシステムをテストできます。
- スーパーステップのタイムラインと実行ツリーを読み取れる。
- 呼び出し上限、ツール上限、ガードをミドルウェアとしてエージェントに追加できる。

## 章

1. [MCP：サーバーが提供するツール](01-mcp.md): エージェントがMCPサーバーのツールを見つけて呼び出す方法と、2026-07-28プロトコルが危険な呼び出しの前に人に確認する方法。
2. [A2A：エージェントに任せるエージェント](02-a2a.md): あるエージェントがAgent Cardを通じて別のエージェントを見つけ、最後まで追えるタスクを渡す方法。
3. [エージェントとインターフェース：AG-UIとA2UI](03-agents-and-uis.md): AG-UIでエージェントの作業をアプリへストリーミングし、A2UIでエージェントに安全なインターフェース部品を記述させる方法。
4. [支払うエージェント：UCPとAP2](04-agent-commerce.md): エージェントがUCPで加盟店のチェックアウトを進める方法と、AP2のマンデートが支払いを人の署名した内容に結びつける方法。
5. [オーケストレーション：スーパーバイザー、ファンアウト、サブグラフ](05-orchestration.md): 1つのLangGraphのグラフで複数のエージェントを動かすパターン：振り分けるスーパーバイザー、並列作業のためのSend、サブグラフ、各スーパーステップが保存するチェックポイント。
6. [コンテキストエンジニアリングと検索](06-context-engineering.md): 各モデル呼び出しが何を読むかを選ぶ：grepかベクトル検索か、大きな結果の退避、サブエージェントの初歩、スレッドをまたいで残るメモリ。
7. [オブザーバビリティ：トレースと実行](07-observability.md): すべてのモデル呼び出し、ツール呼び出し、ステップを実行のツリーとして記録し、それを読んで遅い箇所や壊れた箇所を見つけます。
8. [評価と安全性](08-evaluation-and-safety.md): ケースと確認でエージェントシステムをテストし、インジェクションと改ざんで攻撃し、失敗をOWASPのエージェント型リスクに対応づけます。
