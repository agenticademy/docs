# 標準を、やさしい言葉で

みんなのためのエージェント入門 · 第6章（全8章） · 14分

標準とは、取り決められたメッセージの形式です。これがあるので、別々の人が作ったエージェント、ツール、アプリ、ショップが一緒に動けます。

## 目標

- 一連の流れの各接続に、正しい標準を差し込みましょう。
- 本物のメッセージを1つ開き、各フィールドの意味を読みましょう。
- 確認問題に合格しましょう。

## 本文

### なぜ標準なのか

標準とは、メッセージの書き方の取り決めで、プラグの形に少し似ています。みんなが同じ形で作れば、どのプラグもどのコンセントに合います。標準がなければ、エージェントは一緒に動くアプリ、ツール、ほかのエージェントごとに、専用の配線が必要になります。標準があれば、企業は自分の側を一度作るだけで、多くの相手とつながれます。

ここでいうメッセージとは、あるプログラムが別のプログラムに送る、小さな構造化されたテキストです。誰宛てか、何を頼んでいるか、その詳細が入っています。シミュレーションで本物のメッセージを見られます。

### 4種類の接続

人が使うアプリとエージェントの間：AG-UI（Agent–User Interaction Protocol）は会話を運び、書かれていく途中の返事も運びます。A2UI（Agent-to-User Interface）は、エージェントがフォームなどの画面を記述し、それをアプリが描けるようにします。

エージェント同士の間：A2A（Agent2Agent Protocol）は、あるエージェントが別のエージェントに、たとえ別の会社が動かしているものでも、タスクを渡し、終わるまで追えるようにします。ANP（Agent Network Protocol）は、オープンなウェブで出会うエージェントのためのものです。

エージェントとそのツールの間：MCP（Model Context Protocol）は、ヘルプデスクの注文検索のように、ほかの誰かが動かしているツールを、エージェントが見つけて使えるようにします。

エージェントとショップや支払いの間：UCP（Universal Commerce Protocol）は、エージェントがショップで購入手続きをするための共通の方法を提供し、AP2（Agent Payments Protocol）は、あなたが同意した証拠があるときだけエージェントが支払えるようにします。

### 標準であるもの、ないもの

標準は製品でも、アプリでも、会社でもありません。メッセージを文章で記述したもので、誰でもそれに沿って作れます。これらの標準はまだ新しく、最初に登場したMCPが2024年の終わりで、ほとんどはそれより新しいものです。今も変わり続けているので、どれかについて読むときは、日付とバージョンを確認しましょう。

## 確認問題

### 質問1/3

エージェントとそのツールをつなぐ標準はどれですか？

- A2A
- **✓** MCP
- AG-UI

**理由:** MCP（Model Context Protocol）は、ほかの誰かが動かしているツールをエージェントが見つけて呼び出すための方法です。A2Aはエージェント同士を、AG-UIはアプリとエージェントをつなぎます。

### 質問2/3

A2Aは何のためのものですか？

- **✓** あるエージェントが、ほかの誰かが動かしている別のエージェントにタスクを頼むため。
- アプリにボタンを描くため。
- ショップで支払うため。

**理由:** A2A（Agent2Agent）は、あるエージェントが別のエージェントにタスクを渡し、終わるまで追えるようにします。画面を描くのはA2UIの役目で、支払いはAP2の役目です。

### 質問3/3

ここでいう意味での「標準」とは何ですか？

- 買う製品。
- **✓** 誰でもそれに沿って作れる、メッセージの取り決められた形式。
- AIについての法律。

**理由:** プラグの形のように、標準はメッセージの形を決めるので、別々の人が作った部品が組み合わさります。製品でも法律でもありません。

## これでできること

- 標準とは何か、なぜエージェントに標準が必要かを説明する。
- 接続の種類ごとの標準を挙げる：アプリ、エージェント、ツール、支払い。
- 助けを借りて、本物のエージェントのメッセージの主なフィールドを読む。
